## Purpose

The grouping feature allows the SfGrid to organize data rows into hierarchical caption groups based on one or more column field values. It manages group drop-area rendering, caption row generation, expand/collapse state, lazy loading, virtualization integration, and event notification for both before and after grouping/ungrouping operations.

---

## Requirements

### Requirement: EnableGrouping

`SfGrid` SHALL expose an `AllowGrouping` boolean property (default `false`). When `true`, the grid enables all grouping interactions including drag-to-group, toggle buttons, and programmatic APIs. When `false`, calls to `GroupColumnAsync` and `UnGroupColumn` SHALL be no-ops.

#### Scenario: GroupingEnabledByDefault
- **GIVEN** a grid with `AllowGrouping="false"` (default)
- **WHEN** `GroupColumnAsync("CustomerID")` is invoked
- **THEN** the column is NOT added to `GroupSettings.Columns` and the grid does not re-render grouped rows

#### Scenario: GroupingAllowed
- **GIVEN** a grid with `AllowGrouping="true"`
- **WHEN** `GroupColumnAsync("CustomerID")` is invoked
- **THEN** `"CustomerID"` is appended to `GroupSettings.Columns`, a sort entry is added for that column, and the grid re-renders with grouped caption rows

### Requirement: GroupSettingsComponent

`GridGroupSettings` SHALL be a cascading child component of `SfGrid` that configures grouping behavior through the following properties:

| Property | Type | Default | Description |
|---|---|---|---|
| `AllowReordering` | bool | false | Allows grouped chip elements to be reordered in the drop area |
| `Columns` | string[] | null | Column field names to group on initial render; reflects current grouped state |
| `DisablePageWiseAggregates` | bool | false | When true, calculates aggregate from whole dataset instead of page data |
| `ShowDropArea` | bool | **true** | Controls visibility of the group drop area banner |
| `ShowGroupedColumn` | bool | false | When false, hides the source column after grouping |
| `ShowToggleButton` | bool | false | Shows toggle buttons in column headers for group/ungroup |
| `ShowUngroupButton` | bool | **true** | Shows ungroup button on each grouped chip |
| `EnableLazyLoading` | bool | false | Renders only top-level caption rows collapsed; child rows load on expand |
| `ExpandAllGroups` | bool | false | Auto-expands all groups on initial render (only effective when `EnableVirtualization=true`; ignored if `EnableLazyLoading=true`) |
| `PersistGroupState` | bool | false | Retains expand/collapse state across sort, filter, page, edit, and Refresh operations |
| `CaptionTemplate` | RenderFragment<object> | null | Custom Razor template for group caption cells; context is `CaptionTemplateContext` |

`GridGroupSettings` SHALL call `Parent.UpdateChildProperties("GroupSettings", this)` during `OnInitializedAsync` and notify `BaseParent.PropertyChanged()` whenever any tracked property changes in `OnParametersSetAsync`.

#### Scenario: ShowDropAreaDefault
- **GIVEN** a grid with `AllowGrouping="true"` and no explicit `GridGroupSettings`
- **WHEN** the grid renders
- **THEN** the group drop area element with CSS class `e-groupdroparea` is visible and displays the localized drop area hint text

#### Scenario: ShowDropAreaHidden
- **GIVEN** `<GridGroupSettings ShowDropArea="false" />`
- **WHEN** the grid renders
- **THEN** the `e-groupdroparea` element is NOT rendered

#### Scenario: ShowGroupedColumnHidden
- **GIVEN** `<GridGroupSettings ShowGroupedColumn="false" />`
- **WHEN** a column is grouped (via drag or `GroupColumnAsync`)
- **THEN** `GridColumn.Visible` is set to `false` (tracked via `IsHiddenByGrouping=true`) and the column disappears from the header row

#### Scenario: ShowGroupedColumnVisible
- **GIVEN** `<GridGroupSettings ShowGroupedColumn="true" />`
- **WHEN** a column is grouped
- **THEN** the grouped column remains visible in the header row

### Requirement: InitialGrouping

When the grid initializes with `GridGroupSettings.Columns` containing one or more field names, the grid SHALL apply grouping and sorting for each listed column during the initial data load.

#### Scenario: InitialGroupingApplied
- **GIVEN** `<GridGroupSettings Columns="@(new[] { "CustomerID" })" />`
- **WHEN** the grid completes `OnInitializedAsync`
- **THEN** `SortSettings.Columns` contains a `GridSortColumn` with `Field="CustomerID"`, `Direction=Ascending`, `IsFromGroup=true`, and the data renders with grouped caption rows for each unique `CustomerID` value

#### Scenario: InitialMultiColumnGrouping
- **GIVEN** `<GridGroupSettings Columns="@(new[] { "CustomerID", "ShipCity" })" />`
- **WHEN** the grid initializes
- **THEN** rows are grouped first by `CustomerID`, then by `ShipCity` within each customer group

### Requirement: GroupColumnOperation

Calling `GroupColumnAsync(string columnName)` on `SfGrid` SHALL add the column to the grouped set, add a sort query for that column, and trigger a `Grouping` (before) event followed by a `Grouped` (after) event with `Action=Add`.

#### Scenario: GroupColumnGuards
- **GIVEN** a grid with `AllowGrouping="true"`
- **WHEN** `GroupColumnAsync` is called with a column that has `AllowGrouping=false`, or the column is already grouped, or it is a fixed column
- **THEN** the operation is silently aborted; no events are fired and no state changes occur

#### Scenario: GroupColumnAddsSort
- **GIVEN** a column `"OrderDate"` not present in `SortSettings.Columns`
- **WHEN** `GroupColumnAsync("OrderDate")` is called
- **THEN** a `GridSortColumn { Field="OrderDate", Direction=Ascending, IsFromGroup=true }` entry is appended to `SortSettings.Columns`

#### Scenario: GroupColumnExistingSort
- **GIVEN** `"OrderDate"` is already in `SortSettings.Columns` with `Direction=Descending`
- **WHEN** `GroupColumnAsync("OrderDate")` is called
- **THEN** the existing sort direction is preserved; no duplicate sort entry is added

#### Scenario: GroupColumnCancelable
- **GIVEN** a `Grouping` event handler that sets `args.Cancel = true`
- **WHEN** `GroupColumnAsync("CustomerID")` is called
- **THEN** `"CustomerID"` is NOT added to `GroupSettings.Columns` and the grid does not re-render

---

### Requirement: UngroupColumnOperation

Calling `UngroupColumnAsync(string columnName)` SHALL remove the column from `GroupSettings.Columns`, restore column visibility, remove the associated sort entry (if the sort was injected by grouping), clear all persisted group states, and fire `Grouping` (before) / `Grouped` (after) events with `Action=Remove`.

#### Scenario: UngroupColumnRestoresVisibility
- **GIVEN** a grid with `ShowGroupedColumn=false` and `"CustomerID"` grouped (column hidden)
- **WHEN** `UngroupColumnAsync("CustomerID")` is called
- **THEN** `GridColumn.Visible` is restored to `true` and `IsHiddenByGrouping` is reset to `false`

#### Scenario: UngroupRemovesSortEntry
- **GIVEN** `"CustomerID"` was grouped (sort entry injected by `GroupAddSortingQuery`)
- **WHEN** `UngroupColumnAsync("CustomerID")` is called
- **THEN** the `GridSortColumn` for `"CustomerID"` is removed from `SortSettings.Columns` and from `SortedColumns`

---

### Requirement: ClearGrouping

`ClearGroupingAsync()` SHALL remove all grouped columns from `GroupSettings.Columns` in a single operation, fire `Grouped` with `Action=Reset`, and restore visibility for all columns that were hidden by grouping.

#### Scenario: ClearGroupingResetsAll
- **GIVEN** columns `"CustomerID"` and `"ShipCity"` are grouped
- **WHEN** `ClearGroupingAsync()` is called
- **THEN** `GroupSettings.Columns` is empty, both columns are visible (if previously hidden), and the `Grouped` event fires with `Action=Reset`

---

### Requirement: GroupDropArea

The group drop area SHALL render as an `e-groupdroparea` `<div>` at the top of the grid when `ShowDropArea=true`. It SHALL display a chip (`GroupedHeader`) for each column in `GroupSettings.Columns`. When no columns are grouped it SHALL display the localized placeholder text (`GroupDropArea` locale key).

#### Scenario: DropAreaShowsChips
- **GIVEN** `AllowGrouping="true"`, `ShowDropArea="true"`, and `GroupSettings.Columns = ["CustomerID"]`
- **WHEN** the grid renders
- **THEN** one `GroupedHeader` chip is rendered with `"CustomerID"` label and (when `ShowUngroupButton=true`) an ungroup button

#### Scenario: DropAreaGroupedClass
- **GIVEN** at least one column is grouped
- **WHEN** the drop area renders
- **THEN** the `e-grouped` CSS class is added to the `e-groupdroparea` element; when sticky header is enabled, `e-sticky` is also added

#### Scenario: DropAreaStickyVariant
- **GIVEN** `EnableStickyHeader="true"` and a column is grouped
- **WHEN** the drop area renders
- **THEN** the `e-groupdroparea` element carries both `e-grouped` and `e-sticky` CSS classes

### Requirement: GroupCaptionRow

For each unique value of a grouped column, the `GroupModelGenerator` SHALL produce a `Row<object>` with `RowType="GroupCaption"`, `IsCaptionRow=true`, an `Expand` cell, a `GroupCaption` cell, and indent cells equal to the nesting depth. Caption rows are expanded by default when data is present (except when `EnableLazyLoading=true`).

#### Scenario: CaptionRowDefaultExpanded
- **GIVEN** lazy loading is disabled
- **WHEN** rows are generated for a grouped dataset
- **THEN** all caption rows have `IsExpand=true` and all child data rows have `Visible=true`

#### Scenario: CaptionRowLazyLoadCollapsed
- **GIVEN** `EnableLazyLoading=true`
- **WHEN** rows are generated on initial load
- **THEN** only top-level caption rows are in `Parent.Rows`; child rows are NOT generated until the caption is expanded

#### Scenario: CaptionTextFormat
- **GIVEN** a column `CustomerID` with header text `"Customer ID"` and grouped key `"ALFKI"` containing 2 records
- **WHEN** the group caption cell renders
- **THEN** the caption text is `"Customer ID: ALFKI - 2 Items"` (singular `"Item"` when count is 1)

#### Scenario: CaptionForeignKeyResolution
- **GIVEN** the grouped column is a foreign-key column
- **WHEN** the caption renders
- **THEN** `CaptionTemplateContext.ForeignKey` is populated with the resolved display value from `ForeignKeyValue` data, and `CaptionTemplateContext.ForeignKeyValue` holds the field name

### Requirement: CaptionTemplate

When `GridGroupSettings.CaptionTemplate` is set, the group caption cell SHALL render the user-supplied `RenderFragment<object>` using a `CaptionTemplateContext` context object instead of the default text. The context SHALL expose: `Field`, `Key`, `Count`, `Level`, `HeaderText`, `ForeignKey`, `ForeignKeyValue`, `GroupGuid`, and `GroupAggregates`.

#### Scenario: CaptionTemplateRendered
- **GIVEN** `<GridGroupSettings><CaptionTemplate>@context.HeaderText: @context.Key (@context.Count)</CaptionTemplate></GridGroupSettings>`
- **WHEN** a caption row renders
- **THEN** the template markup is output in place of the default `"Header: Value - N Items"` string

#### Scenario: CaptionTemplateWithAggregate
- **GIVEN** a `GridAggregateColumn` with `GroupCaptionTemplate` set and the grouped column is associated with an aggregate
- **THEN** `CaptionTemplateContext.GroupAggregates` contains the formatted aggregate value (Sum, Average, Max, Min, Count, TrueCount, FalseCount, or Custom)

### Requirement: ExpandCollapseGroups

Clicking a caption row (or pressing `Enter` on it) SHALL toggle its expanded state, show/hide child rows accordingly, and trigger a content state-changed event for re-render. Keyboard shortcuts `Ctrl+Down` / `Ctrl+Up` SHALL expand / collapse all groups.

#### Scenario: ClickToCollapse
- **GIVEN** a caption row with `IsExpand=true`
- **WHEN** the caption cell is clicked
- **THEN** `IsExpand` becomes `false` and all direct child rows (and their descendants) have `Visible=false`

#### Scenario: ClickToExpand
- **GIVEN** a caption row with `IsExpand=false`
- **WHEN** the caption cell is clicked
- **THEN** `IsExpand` becomes `true` and direct child rows become `Visible=true`; deeply nested rows follow their own `IsExpand` state

#### Scenario: ExpandAllGroupsKeyboard
- **GIVEN** focus is on the grid
- **WHEN** `Ctrl+Down` is pressed
- **THEN** `ExpandAllGroupAsync()` is called and all caption rows are set to `IsExpand=true`

#### Scenario: CollapseAllGroupsKeyboard
- **GIVEN** focus is on the grid
- **WHEN** `Ctrl+Up` is pressed
- **THEN** `CollapseAllGroupAsync()` is called and all caption rows are set to `IsExpand=false`

#### Scenario: AltUpCollapsesNearestParent
- **GIVEN** focus is on a data row inside an expanded group
- **WHEN** `Alt+Up` is pressed
- **THEN** the nearest ancestor caption row that is expanded is collapsed

#### Scenario: AltDownExpandsNearestParent
- **GIVEN** focus is on a data row inside a collapsed group
- **WHEN** `Alt+Down` is pressed
- **THEN** the nearest ancestor caption row that is collapsed is expanded

### Requirement: PersistGroupState

When `PersistGroupState=true` and `EnableLazyLoading=false`, the grid SHALL track each caption row's expand/collapse state using a composite `GroupKey` (row key + unique ancestor path) stored in `Parent.GroupStates`. This state SHALL be restored after sort, filter, page, edit, and `Refresh` operations.

#### Scenario: StateRestoredAfterSort
- **GIVEN** `PersistGroupState=true`, group `"ALFKI"` is collapsed
- **WHEN** the user sorts another column
- **THEN** after re-render, the `"ALFKI"` group is still collapsed

#### Scenario: StateResetOnGroupChange
- **GIVEN** `PersistGroupState=true` with saved states
- **WHEN** a column is grouped or ungrouped
- **THEN** `Parent.GroupStates` is cleared (state is reset)

#### Scenario: StateNotPersistedOnReload
- **GIVEN** `PersistGroupState=true`
- **WHEN** the browser page is reloaded or the data source is dynamically replaced
- **THEN** group expand/collapse state is NOT restored (session-only persistence)

---

### Requirement: LazyLoadGrouping

When `EnableLazyLoading=true`, the grid SHALL defer loading child rows until the user expands a caption. On expand, a filtered + grouped data query is built (`FilterQuery` + `GroupQuery`) and executed against the `DataManager`. On collapse, child rows are removed from `LazyRows`.

#### Scenario: LazyLoadExpandFetchesData
- **GIVEN** `EnableLazyLoading=true` and a caption row is collapsed
- **WHEN** the user expands the caption row
- **THEN** a remote/local data query with appropriate `Where` and `Group` predicates is executed; the returned rows are inserted into `LazyRows` after the caption row

#### Scenario: LazyLoadCollapseRemovesRows
- **GIVEN** `EnableLazyLoading=true` and a caption row is expanded
- **WHEN** the user collapses the caption row
- **THEN** all descendant rows are removed from `LazyRows` and `Parent.Rows`

#### Scenario: LazyLoadWithPaging
- **GIVEN** `EnableLazyLoading=true` and `AllowPaging=true`
- **WHEN** a caption is expanded and the expanded rows overflow the page size
- **THEN** only rows fitting within the current page are visible; `TotalItemCount` is updated and the pager refreshes

---

### Requirement: GroupWithVirtualization

When `EnableVirtualization=true` and grouping is active, the grid SHALL use `VirtualScrollModule` to generate visible grouped rows and SHALL call `VirtualScrollModule.SetGeneratedData` after any expand/collapse. `ExpandAllGroups=true` causes all groups to be pre-expanded on initial render; this property is ignored when `EnableLazyLoading=true`.

#### Scenario: VirtualGroupExpandAllOnInit
- **GIVEN** `EnableVirtualization=true`, `EnableLazyLoading=false`, `ExpandAllGroups=true`
- **WHEN** the grid initializes
- **THEN** all caption rows are rendered with `IsExpand=true` and all data rows are in the virtual row set

#### Scenario: VirtualGroupExpandAllIgnoredWithLazy
- **GIVEN** `EnableVirtualization=true`, `EnableLazyLoading=true`, `ExpandAllGroups=true`
- **WHEN** the grid initializes
- **THEN** `ExpandAllGroups` has no effect; groups render collapsed per lazy load behavior

---

### Requirement: GroupFooterAggregates

When `GridAggregates` are configured and `GroupFooterTemplate` or non-captioned aggregate columns exist, `GroupModelGenerator` SHALL generate summary footer rows (`RowType="Summary"`) after each caption group's children.

#### Scenario: GroupFooterRowGenerated
- **GIVEN** a `GridAggregate` with a `GridAggregateColumn` that has `GroupFooterTemplate` set
- **WHEN** rows are generated for a grouped column
- **THEN** a footer `Row<object>` with `RowType="Summary"` is appended after the last child row of each caption group, with `Visible` matching the caption row's `IsExpand`

---

### Requirement: GroupEvents

The grid SHALL expose two events on `GridEvents<TValue>`:
- **`Grouping`** (`GroupingEventArgs`) — fires BEFORE a column is grouped or ungrouped; setting `Cancel=true` aborts the operation.
- **`Grouped`** (`GroupedEventArgs`) — fires AFTER the grouping or ungrouping operation completes.

`GroupingEventArgs` and `GroupedEventArgs` both expose `ColumnName` (affected field) and `Action` (`Add`, `Remove`, or `Reset`).

#### Scenario: GroupingEventFiredBeforeChange
- **GIVEN** a handler for the `Grouping` event
- **WHEN** `GroupColumnAsync("ShipCountry")` is called
- **THEN** the `Grouping` event fires with `ColumnName="ShipCountry"` and `Action=Add` BEFORE `GroupSettings.Columns` is updated

#### Scenario: GroupedEventFiredAfterChange
- **GIVEN** a handler for the `Grouped` event
- **WHEN** `UngroupColumnAsync("ShipCountry")` is called
- **THEN** the `Grouped` event fires with `ColumnName="ShipCountry"` and `Action=Remove` AFTER `GroupSettings.Columns` is updated

#### Scenario: GroupingCancelPreventsGrouped
- **GIVEN** the `Grouping` handler sets `args.Cancel = true`
- **WHEN** grouping is triggered
- **THEN** the `Grouped` event is NOT fired

### Requirement: PublicGroupingAPI

`SfGrid<TValue>` SHALL expose the following async public methods for programmatic grouping:

| Method | Description |
|---|---|
| `GroupColumnAsync(string columnName)` | Programmatically groups the specified column |
| `UngroupColumnAsync(string columnName)` | Removes grouping from the specified column |
| `ExpandAllGroupAsync()` | Expands all group caption rows |
| `CollapseAllGroupAsync()` | Collapses all group caption rows |
| `ClearGroupingAsync()` | Removes all grouping |

#### Scenario: ProgrammaticGroupColumn
- **GIVEN** a grid reference `@ref="grid"` and `AllowGrouping="true"`
- **WHEN** `await grid.GroupColumnAsync("OrderDate")` is called from a button click
- **THEN** the grid re-renders with `"OrderDate"` grouped, identical to a user drag-to-group operation
