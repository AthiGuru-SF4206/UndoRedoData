## Purpose

The Paging feature divides the Grid's data records into discrete pages and renders a `SfPager` component at the Grid footer for navigation. It is configured through the `GridPageSettings` child component and is activated by setting `AllowPaging="true"` on `SfGrid`. Paging integrates with sorting, filtering, grouping, searching, and persistence, always resetting to page 1 when those features change the data set.

---

## Requirements

### Requirement: EnablePaging

The system SHALL render a pager UI at the footer of the Grid when `AllowPaging` is `true`, and SHALL hide it when `AllowPaging` is `false`.

#### Scenario: Pager rendered when AllowPaging is true
- **GIVEN** an `SfGrid` with `AllowPaging="true"` and a data source
- **WHEN** the grid initialises
- **THEN** exactly one element with CSS class `.e-pager` SHALL be present in the DOM

#### Scenario: Pager hidden when AllowPaging is false
- **GIVEN** an `SfGrid` with `AllowPaging="false"`
- **WHEN** the grid renders
- **THEN** no `.e-pager` element SHALL exist in the DOM

#### Scenario: Dynamic toggle of AllowPaging
- **GIVEN** a grid where `AllowPaging` is toggled at runtime via `CallStateHasChangedAsync`
- **WHEN** `AllowPaging` changes from `false` to `true`
- **THEN** the pager SHALL appear
- **WHEN** `AllowPaging` changes from `true` to `false`
- **THEN** the pager SHALL disappear

---

### Requirement: DefaultPageSettings

The system SHALL use the following defaults when no `<GridPageSettings>` is provided:

| Property       | Default |
|----------------|---------|
| `CurrentPage`  | `1`     |
| `PageSize`     | `12`    |
| `PageCount`    | `8`     |
| `PageSizes`    | `null`  |
| `EnableQueryString` | `false` |

The system SHALL auto-correct `PageSize` back to `12` if it is set to `0`.

#### Scenario: Grid renders correct row count on first page
- **GIVEN** `AllowPaging="true"` with a data source of 20 records and default `PageSize` of 12
- **WHEN** the grid renders
- **THEN** exactly 12 `.e-row` elements SHALL be present and `CurrentViewData.Count` SHALL equal 12

### Requirement: ConfigurablePageSettings

The system SHALL honour explicit `GridPageSettings` properties to control pager appearance and behaviour.

#### Scenario: PageSize limits visible rows
- **GIVEN** `<GridPageSettings PageSize="2">`
- **WHEN** the grid renders
- **THEN** exactly 2 rows SHALL be displayed per page

#### Scenario: CurrentPage sets the initial page
- **GIVEN** `<GridPageSettings CurrentPage="2" PageSize="2">`
- **WHEN** the grid renders
- **THEN** `PageSettings.CurrentPage` SHALL equal `2`

#### Scenario: PageCount controls numeric buttons in pager
- **GIVEN** `<GridPageSettings PageCount="4">`
- **WHEN** the grid renders
- **THEN** the numeric container SHALL contain 4 page-number links

#### Scenario: TotalItemCount reflects the full data source
- **GIVEN** a data source with 20 records and `AllowPaging="true"`
- **WHEN** the grid renders
- **THEN** `TotalItemCount` SHALL equal `20`

### Requirement: PageNavigation

The system SHALL update `CurrentViewData` and re-render rows when the user navigates to a different page.

#### Scenario: Clicking a page number updates rows
- **GIVEN** a grid on page 1 with `PageSize="12"` and 20 total records
- **WHEN** the user clicks the link for page 2
- **THEN** 8 rows SHALL be rendered (the remaining records) and `CurrentViewData.Count` SHALL equal `8`

#### Scenario: GoToPageAsync navigates programmatically
- **GIVEN** `AllowPaging="true"` and the grid is on page 1
- **WHEN** `await grid.GoToPageAsync(4)` is called
- **THEN** the grid SHALL navigate to page 4 and refresh the view
- **WHEN** `AllowPaging` is `false`
- **THEN** `GoToPageAsync` SHALL be a no-op and SHALL NOT throw

---

### Requirement: ActionEvents

The system SHALL fire `OnActionBegin` before a page change and `OnActionComplete` after the new page is rendered, both carrying `RequestType = "paging"`.

#### Scenario: OnActionBegin fires with paging request type
- **GIVEN** a grid with an `OnActionBegin` event handler
- **WHEN** the user navigates to a different page
- **THEN** `OnActionBegin` SHALL be invoked with `args.RequestType == "paging"`

#### Scenario: Cancelling paging in OnActionBegin
- **GIVEN** an `OnActionBegin` handler that sets `args.Cancel = true` when `RequestType == "paging"`
- **WHEN** the user attempts to navigate to page 2
- **THEN** the active page indicator SHALL remain on page 1 (`.e-active` text SHALL equal `"1"`)
- **AND** no data refresh SHALL occur

---

### Requirement: PageSizesDropdown

The system SHALL render a dropdown in the pager when `PageSizes` is set, allowing the user to change the number of records per page.

#### Scenario: Custom PageSizes array renders dropdown options
- **GIVEN** `<GridPageSettings PageSizes="@(new int[]{ 10, 20, 30, 40 })">`
- **WHEN** the grid renders
- **THEN** a page-size dropdown SHALL be visible in the pager

#### Scenario: Changing PageSize via dropdown refreshes rows
- **GIVEN** `PageSizes` is configured and the dropdown is visible
- **WHEN** `PageSettings.PageSize` is programmatically changed to `30`
- **THEN** the grid SHALL display up to 30 rows on the current page

#### Scenario: PageSizes="true" enables the "All" option
- **GIVEN** `<GridPageSettings PageSizes="true">`
- **WHEN** the user selects the "All" option from the dropdown
- **THEN** all records SHALL be rendered on a single page (`CurrentViewData.Count` SHALL equal the total record count)

#### Scenario: Changing PageSize resets to page 1
- **GIVEN** the grid is on page 3 with `PageSize="2"`
- **WHEN** `PageSettings.PageSize` is changed to `8`
- **THEN** `PageSettings.CurrentPage` SHALL reset to `1`

### Requirement: PagerTemplate

The system SHALL support a `<Template>` inside `GridPageSettings` that replaces the default pager UI with custom markup.

#### Scenario: Custom pager template is rendered
- **GIVEN** a `<Template>` is defined inside `GridPageSettings`
- **WHEN** the grid renders
- **THEN** `PageSettings.Template` SHALL NOT be null/empty
- **AND** the custom template markup SHALL appear in place of the default pager

#### Scenario: Template re-renders on Refresh
- **GIVEN** a grid with a pager template and an `OnActionComplete` handler
- **WHEN** `await grid.Refresh()` is called
- **THEN** `OnActionComplete` SHALL be invoked exactly once

---

### Requirement: ExternalFilterMessage

The system SHALL display a filter description message in the pager external message area when a filter is applied while paging is active.

#### Scenario: Filter message shown in pager after filtering
- **GIVEN** `AllowPaging="true"` and `AllowFiltering="true"`
- **WHEN** `FilterByColumnAsync("CustomerID", "equal", "anton")` is called
- **THEN** the `.e-pagerexternalmsg` element SHALL contain the text `"CustomerID: anton"`

---

### Requirement: EnableQueryString

The system SHALL append the current page number as a query string parameter in the browser URL when `EnableQueryString` is `true`.

#### Scenario: Query string appended on page navigation
- **GIVEN** `<GridPageSettings EnableQueryString="true">`
- **WHEN** the user navigates to page 3
- **THEN** the URL SHALL contain the page number as a query string parameter

---

### Requirement: PageQuery

The system SHALL include a `Page(currentPage, pageSize)` clause in the data query when `AllowPaging` is `true` and lazy-load grouping is not active, so the server or in-memory engine returns only the records for the current page.

#### Scenario: Page query sent for current page
- **GIVEN** `AllowPaging="true"` with `CurrentPage=2` and `PageSize=10`
- **WHEN** `DataGenerator.PageQuery` executes
- **THEN** the query SHALL contain `Page(2, 10)` (i.e. skip 10, take 10)

#### Scenario: Page query skipped for grouped lazy-load
- **GIVEN** `AllowPaging="true"` and `GroupSettings.EnableLazyLoading=true` with grouped columns
- **WHEN** the data query is generated
- **THEN** `PageQuery` SHALL NOT add a page clause to the query

---

### Requirement: PageResetOnDataChange

The system SHALL reset `CurrentPage` to `1` when a data-altering action (filtering, searching, grouping) is performed so that the user is always on a valid page.

#### Scenario: Filtering resets current page
- **GIVEN** the grid is on page 3 with paging enabled
- **WHEN** a filter is applied
- **THEN** `PageSettings.CurrentPage` SHALL reset to `1` before data is fetched

#### Scenario: Page out-of-range corrected with persistence
- **GIVEN** `EnablePersistence="true"` and the persisted `CurrentPage` exceeds the maximum available page for the current data set
- **WHEN** the grid loads with the persisted state
- **THEN** the system SHALL automatically navigate to the last valid page

---

### Requirement: StatesPersistence

The system SHALL persist `CurrentPage` and `PageSize` across browser page reloads when `EnablePersistence` is `true`.

#### Scenario: Paging state restored on reload
- **GIVEN** `EnablePersistence="true"` and the user is on page 4 with `PageSize="5"`
- **WHEN** the page is reloaded
- **THEN** the grid SHALL restore `CurrentPage=4` and `PageSize=5` from the persisted state

## Technical Notes

- **Implementation**:
  - `GridPageSettings.razor.cs` — Paging settings component; properties: `CurrentPage`, `PageSize`, `PageCount`, `PageSizes`, `EnableQueryString`, `Template`, `EnableExternalMessage`, `ExternalMessage`
  - `SfGrid.Properties.cs` — `AllowPaging` (`bool`, default `false`) and `PageSettings` (`GridPageSettings?`) grid-level properties
  - `SfGrid.razor.cs` — `TotalItemCount` (int), pager event handling (`GridPageChangingEventArgs`), `ModelChanged` with `RequestType = Action.Paging`, `PageNavHandler`, out-of-range page correction
  - `SfGrid.Methods.cs` — `GoToPageAsync(int pageNo)` public API method
  - `Internal/Actions/Data.cs` — `PageQuery(Query, bool skipPage, ...)` appends `query.Page(CurrentPage, PageSize)` to the data query
  - `SfGrid.Lifecycle.cs` — registers `PageSettings` in `OnInitializedAsync` and synchronises it in `OnParametersSetAsync`

- **Dependencies**:
  - `Syncfusion.Blazor.Navigations.SfPager` — external pager component referenced via `PagerRef`
  - `Syncfusion.Blazor.Navigations.PagerTemplateContext` — context type for the pager `Template`
  - Filtering feature — applies `FilterQuery` before `PageQuery` in `DataGenerator.GenerateQuery`
  - Sorting feature — applies `SortQuery` before `PageQuery`
  - Grouping feature — `GroupSettings.EnableLazyLoading` suppresses `PageQuery` for grouped data
  - Virtual Scrolling — replaces `PageQuery` with `Range` query when `EnableVirtualization` is active
  - Infinite Scrolling — replaces `PageQuery` with `IntialInfinitePageQuery` when `EnableInfiniteScrolling` is active
  - State Persistence — `EnablePersistence` restores `CurrentPage` and `PageSize` via `CallStateHasChangedAsync`
