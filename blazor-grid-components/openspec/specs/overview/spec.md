## Purpose

The overview domain defines what the Syncfusion Blazor Grid component exposes at package and component level. It describes the main feature switches, public property surface, and the high-level lifecycle used to initialize, render, and refresh the grid.

## Requirements

### Requirement: PackageAndTargetFrameworks

The grid package MUST target multiple .NET frameworks and SHALL publish as a Razor component package with grid-specific metadata.

#### Scenario: MultiTargetBuildConfiguration
- **GIVEN** the grid project file is evaluated
- **WHEN** `TargetFrameworks` is read
- **THEN** the project SHALL target `net8.0`, `net9.0`, and `net10.0`

#### Scenario: PackageIdentityConfiguration
- **GIVEN** package metadata is read from the project file
- **WHEN** NuGet identity fields are evaluated
- **THEN** the package SHALL use `PackageId=Syncfusion.Blazor.Grid` and `AssemblyName=Syncfusion.Blazor.Grids`

### Requirement: PublicGridContract

The grid component SHALL expose a broad public contract through `SfGrid<TValue>` and `IGrid` for data, interaction, and feature configuration.

#### Scenario: IGridDefinesFeatureSwitches
- **GIVEN** the `IGrid` interface
- **WHEN** feature properties are inspected
- **THEN** the contract SHALL include toggles such as `AllowPaging`, `AllowSorting`, `AllowFiltering`, `AllowGrouping`, and `EditSettings`

#### Scenario: SfGridExposesBlazorParameters
- **GIVEN** `SfGrid.Properties.cs`
- **WHEN** parameter declarations are inspected
- **THEN** grid capabilities SHALL be configured through `[Parameter]` properties on `SfGrid<TValue>`

### Requirement: ModuleInitializationLifecycle

The grid lifecycle MUST initialize its feature modules during component initialization.

#### Scenario: OnInitializedCreatesCoreModules
- **GIVEN** `OnInitializedAsync` executes
- **WHEN** module setup runs
- **THEN** the grid SHALL instantiate modules for sorting, grouping, filtering, selection, editing, virtual scroll, and row reorder

#### Scenario: OnInitializedCreatesInteropAdaptor
- **GIVEN** `OnInitializedAsync` executes
- **WHEN** initialization reaches client integration
- **THEN** `_jsAdaptor` SHALL be created as `GridJSInteropAdaptor<TValue>`

### Requirement: RenderComposition

The root grid render tree SHALL compose optional UI blocks based on runtime settings.

#### Scenario: ValidationDialogRenderedForCrud
- **GIVEN** add, edit, or delete is enabled in `EditSettings`
- **WHEN** the grid renders the root component
- **THEN** `ValidationDialog` SHALL be included in the render tree

#### Scenario: PagingRendersPagerComponent
- **GIVEN** `AllowPaging` is `true`
- **WHEN** the grid renders
- **THEN** `SfPager` SHALL be rendered with current page and page size settings

### Requirement: PropertyChangeRefreshPipeline

The grid SHALL process parameter changes and trigger refresh actions only when relevant tracked properties change.

#### Scenario: DataSourceChangeResetsSelectionState
- **GIVEN** `DataSource` changes in `OnParametersSetAsync`
- **WHEN** property change handling executes
- **THEN** selected row and checkbox persisted selection state SHALL be reset

#### Scenario: RefreshActionRaisedForRefreshableChanges
- **GIVEN** refreshable property changes are detected
- **WHEN** reset mode is not active
- **THEN** `ModelChanged` SHALL be invoked with `RequestType=Action.Refresh`
