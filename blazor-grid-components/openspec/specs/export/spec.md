## Purpose

The Export domain handles serialization of the Syncfusion Blazor Grid data to Excel (.xlsx), CSV (.csv), and PDF formats. It covers data retrieval, header/stacked-header generation, grouped row rendering, aggregate (summary) rows, detail template rows, theming/styling, custom column overrides, and both browser-download and `MemoryStream` return paths. Every export path is gated by a boolean property (`AllowExcelExport` / `AllowPdfExport`) and raises a pair of lifecycle events (before-export start and after-export complete).

## Requirements

---

### Requirement: EnableExcelExport

The component SHALL expose `AllowExcelExport` (type `bool`, default `false`). When `AllowExcelExport` is `false` the `ExportToExcelAsync` and `ExportToCsvAsync` methods SHALL be no-ops and return `null`.

#### Scenario: ExcelExportBlockedWhenNotAllowed
- **GIVEN** an `SfGrid` with `AllowExcelExport="false"`
- **WHEN** `ExportToExcelAsync()` is called programmatically
- **THEN** no workbook is created and no browser download is triggered

#### Scenario: ExcelExportAllowedWhenEnabled
- **GIVEN** an `SfGrid` with `AllowExcelExport="true"`
- **WHEN** `ExportToExcelAsync()` is called
- **THEN** `GridExcelExport<TValue>.ExcelExport` is invoked and the resulting `.xlsx` stream is pushed to the browser via `sfBlazor.Grid.exportSave`

---

### Requirement: EnablePdfExport

The component SHALL expose `AllowPdfExport` (type `bool`, default `false`). When `AllowPdfExport` is `false` the `ExportToPdfAsync` method SHALL be a no-op and return `null`.

#### Scenario: PdfExportBlockedWhenNotAllowed
- **GIVEN** an `SfGrid` with `AllowPdfExport="false"`
- **WHEN** `ExportToPdfAsync()` is called
- **THEN** no PDF document is created and no browser download is triggered

#### Scenario: PdfExportAllowedWhenEnabled
- **GIVEN** an `SfGrid` with `AllowPdfExport="true"`
- **WHEN** `ExportToPdfAsync()` is called
- **THEN** `GridPdfExport<TValue>.PdfExport` is invoked and the resulting `.pdf` stream is pushed to the browser via `sfBlazor.Grid.exportSave`

---

### Requirement: CsvExport

The component SHALL support CSV export by reusing the Excel export pipeline with `IsCsvExport = true` and a default file name of `Export.csv`. The `ExportToCsvAsync` method MUST accept optional `ExcelExportProperties`.

#### Scenario: CsvExportDefaultFileName
- **GIVEN** `AllowExcelExport="true"` and no `ExcelExportProperties` provided
- **WHEN** `ExportToCsvAsync()` is called
- **THEN** the downloaded file is named `Export.csv`

#### Scenario: CsvExportCustomFileName
- **GIVEN** `AllowExcelExport="true"` and `ExcelExportProperties { FileName = "report.csv" }`
- **WHEN** `ExportToCsvAsync(properties)` is called
- **THEN** the downloaded file is named `report.csv`

---

### Requirement: MemoryStreamExport

All three export methods (`ExportToExcelAsync`, `ExportToCsvAsync`, `ExportToPdfAsync`) SHALL provide overloads that accept `bool asMemoryStream`. When `asMemoryStream = true` the rendered document MUST be returned as a `MemoryStream` and no browser download SHALL be triggered.

#### Scenario: ExcelMemoryStreamReturn
- **GIVEN** `AllowExcelExport="true"`
- **WHEN** `ExportToExcelAsync(asMemoryStream: true)` is called
- **THEN** a non-null `MemoryStream` is returned and `sfBlazor.Grid.exportSave` is NOT called

#### Scenario: PdfMemoryStreamReturn
- **GIVEN** `AllowPdfExport="true"`
- **WHEN** `ExportToPdfAsync(asMemoryStream: true)` is called
- **THEN** a non-null `MemoryStream` is returned and `sfBlazor.Grid.exportSave` is NOT called

---

### Requirement: ExportTypeAllPagesVsCurrentPage

The `ExcelExportProperties.ExportType` and `PdfExportProperties.ExportType` properties (enum `ExportType`: `AllPages` | `CurrentPage`) SHALL control whether `ExportHelper<T>.DataProcess` fetches all records or only the current page's records.

#### Scenario: AllPagesExport
- **GIVEN** a paged grid with 3 pages and `ExportType = AllPages`
- **WHEN** export is triggered
- **THEN** all records across all pages are included in the output document

#### Scenario: CurrentPageExport
- **GIVEN** a paged grid on page 2 and `ExportType = CurrentPage`
- **WHEN** export is triggered
- **THEN** only the records visible on page 2 are included in the output document

---

### Requirement: CustomDataSource

`ExcelExportProperties.DataSource` and `PdfExportProperties.DataSource` MAY be set to override the grid's bound data source for the export. When set and the value is a plain `IEnumerable<object>`, it MUST be used directly without querying the grid's `DataManager`.

#### Scenario: OverrideDataSourceOnExport
- **GIVEN** a grid bound to 100 rows and `ExcelExportProperties { DataSource = customList }` where `customList` has 5 rows
- **WHEN** `ExportToExcelAsync(properties)` is called
- **THEN** the exported workbook contains exactly 5 rows of data

---

### Requirement: ColumnSubset

`ExcelExportProperties.Columns` and `PdfExportProperties.Columns` MAY contain a subset of `GridColumn` definitions. When provided, only those columns SHALL appear in the export output.

#### Scenario: SubsetColumnsExport
- **GIVEN** a grid with 5 columns and `ExcelExportProperties.Columns` listing 2 of them
- **WHEN** export runs
- **THEN** the generated worksheet/PDF contains exactly 2 data columns

---

### Requirement: IncludeHiddenColumns

`ExcelExportProperties.IncludeHiddenColumn` (bool, default `false`) and the equivalent PDF property SHALL control whether columns with `Visible = false` are included in the export.

#### Scenario: HiddenColumnsExcludedByDefault
- **GIVEN** a grid with one hidden column (`Visible="false"`) and no export properties override
- **WHEN** export runs
- **THEN** the hidden column does not appear in the output document

#### Scenario: HiddenColumnsIncludedWhenEnabled
- **GIVEN** `ExcelExportProperties { IncludeHiddenColumn = true }`
- **WHEN** export runs
- **THEN** the previously hidden column is present in the output document

---

### Requirement: IncludeTemplateColumns

`ExcelExportProperties.IncludeTemplateColumn` (bool, default `false`) SHALL control whether columns that have a `Template` defined are included in the Excel/CSV export output.

#### Scenario: TemplateColumnExcludedByDefault
- **GIVEN** a grid with a template column and no export properties override
- **WHEN** export runs
- **THEN** the template column is absent from the output document

#### Scenario: TemplateColumnIncludedWhenEnabled
- **GIVEN** `ExcelExportProperties { IncludeTemplateColumn = true }`
- **WHEN** export runs
- **THEN** the template column appears in the output document (cell value resolved from data field)

---

### Requirement: IncludeCommandColumns

`ExcelExportProperties.IncludeCommandColumn` and the equivalent PDF property (bool, default `false`) SHALL control whether columns of type `Commands` are included in export output.

---

### Requirement: HeaderRow

By default the exported document SHALL include a column header row. Setting `ExcelExportProperties.IncludeHeaderRow = false` or the PDF equivalent SHALL suppress the header row entirely.

#### Scenario: HeaderRowSuppressed
- **GIVEN** `ExcelExportProperties { IncludeHeaderRow = false }`
- **WHEN** export runs
- **THEN** the output document starts directly with data rows — no header row is present

---

### Requirement: StackedHeaders

When the grid has stacked (multi-level) column headers (`GridColumn.Columns` is non-null), the export engine MUST render all header levels using row-span and column-span to match the visual stacked structure.

#### Scenario: StackedHeadersPreservedInExcel
- **GIVEN** a grid with a two-level stacked column header
- **WHEN** `ExportToExcelAsync()` is called
- **THEN** the Excel output contains two header rows where parent header cells span the appropriate number of child columns

#### Scenario: StackedHeadersPreservedInPdf
- **GIVEN** a grid with a two-level stacked column header
- **WHEN** `ExportToPdfAsync()` is called
- **THEN** the PDF grid has two header rows with correct `ColumnSpan` / `RowSpan` values

---

### Requirement: GroupingInExport

When the grid has `AllowGrouping = true` and `GroupSettings.Columns` contains at least one field, the export engine SHALL render group caption rows with indent cells, inline group-caption summary (if `GroupCaptionTemplate` is present), and nested data rows that reflect the grouping hierarchy.

#### Scenario: GroupCaptionRowRendered
- **GIVEN** a grid grouped by one field
- **WHEN** export runs
- **THEN** each distinct group value produces a caption row in the output document

#### Scenario: NestedGroupExport
- **GIVEN** a grid grouped by two fields (two-level nesting)
- **WHEN** export runs
- **THEN** each outer group contains inner group caption rows followed by their respective data rows

---

### Requirement: AggregateRowsInExport

When the grid has `GridAggregates` configured, the export engine SHALL render summary (aggregate) rows at the appropriate position: group footer rows for grouped data and a grand-total footer row at the end of the document. The aggregate value and number format SHALL be applied consistently with the column's `Format` property.

#### Scenario: FooterAggregateRow
- **GIVEN** a grid with a footer aggregate (`FooterTemplate` set on `GridAggregateColumn`)
- **WHEN** export runs
- **THEN** a summary row appears after all data rows with the correct aggregate value

#### Scenario: GroupFooterAggregateRow
- **GIVEN** a grid that is grouped and has a group-footer aggregate (`GroupFooterTemplate` set)
- **WHEN** export runs
- **THEN** each group's data rows are followed by a group-summary row

#### Scenario: GroupCaptionAggregateInline
- **GIVEN** a grid that is grouped and has a caption aggregate (`GroupCaptionTemplate` set)
- **WHEN** export runs
- **THEN** the aggregate value appears inline in the group caption row at the correct column index

---

### Requirement: DetailTemplateExport

When a grid has a `DetailTemplate` and `ExcelExportProperties.ExcelDetailRowMode` is `ExcelDetailRowMode.Expand` or `ExcelDetailRowMode.Collapse`, the `ExcelDetailTemplateExporting` event SHALL be raised for each parent row. The consumer MUST populate `ExcelDetailTemplateEventArgs.RowInfo` to render detail sub-rows. When mode is `Collapse`, detail rows SHALL be rendered with `Grouping.IsCollapsed = true` and `Grouping.IsHidden = true`.

#### Scenario: DetailRowExpandedInExcel
- **GIVEN** a grid with `DetailTemplate`, `ExcelDetailRowMode = Expand`, and `ExcelDetailTemplateExporting` handler that sets `RowInfo.Rows`
- **WHEN** `ExportToExcelAsync()` runs
- **THEN** a detail row is appended after each parent row in the workbook with the specified cell values

#### Scenario: DetailRowCollapsedInExcel
- **GIVEN** `ExcelDetailRowMode = Collapse`
- **WHEN** export runs
- **THEN** each detail row exists in the workbook but is marked as hidden and collapsed

#### Scenario: PdfDetailRowExpanded
- **GIVEN** a grid with `DetailTemplate`, `PdfDetailRowMode = Expand`, and `PdfDetailTemplateExporting` handler
- **WHEN** `ExportToPdfAsync()` runs
- **THEN** the PDF grid contains an extra row per parent row rendered as a nested `PdfGrid` within the detail cell

### Requirement: ExcelQueryCellInfo

The `ExcelQueryCellInfoEvent` SHALL be raised for every data cell that is rendered during Excel/CSV export. The event argument SHALL expose the `Cell` (type `Cell`), `Column` (`GridColumn`), `Style` (`CellStyle`), `Data` (row data `TValue`), `Value` (resolved cell value), `ColSpan`, `ColumnIndex`, and `RowIndex`.

#### Scenario: ExcelQueryCellInfoRaisedPerCell
- **GIVEN** `ExcelQueryCellInfoEvent` is subscribed
- **WHEN** export runs with 3 data rows and 2 exportable columns
- **THEN** the event is raised 6 times (once per cell)

#### Scenario: ExcelQueryCellInfoCustomStyle
- **GIVEN** handler sets `args.Style.BackColor = "#FF0000"` for a specific column
- **WHEN** export runs
- **THEN** the corresponding Excel cell has a red background fill

---

### Requirement: ExcelHeaderQueryCellInfo

The `ExcelHeaderQueryCellInfoEvent` SHALL be raised for every header cell rendered during Excel/CSV export. The argument SHALL expose `Cell`, `Column`, `Style`, `Value`, `Colspan`, `ColumnIndex`, and `RowIndex`.

#### Scenario: HeaderCellCustomization
- **GIVEN** `ExcelHeaderQueryCellInfoEvent` sets `args.Style.Bold = true`
- **WHEN** export runs
- **THEN** all header cells in the worksheet are bold

---

### Requirement: ExcelAggregateTemplateInfo

The `ExcelAggregateTemplateInfo` event SHALL be raised for every rendered aggregate cell in the Excel/CSV output. The argument SHALL expose `Cell`, `Column` (`GridAggregateColumn`), `Value`, `Style`, `GroupKey`, and `AggregateType` (`Footer` | `GroupFooter` | `GroupCaption`).

---

### Requirement: ExcelGroupCaptionTemplateInfo

When `GridGroupSettings.CaptionTemplate` is configured and `ExcelGroupCaptionTemplateInfo` is subscribed, the event SHALL be raised for each group caption row during Excel export. The argument SHALL expose `Cell`, `Column`, `Value`, `Style`, `Count`, `Field`, `HeaderText`, and `Key`.

---

### Requirement: PdfQueryCellInfo

The `PdfQueryCellInfoEvent` SHALL be raised for every data cell rendered during PDF export. The argument SHALL expose `Cell` (`PdfGridCell`), `Column`, `Style`, `Data`, `Value`, `Colspan`, `ColumnIndex`, and `RowIndex`.

---

### Requirement: PdfHeaderQueryCellInfo

The `PdfHeaderQueryCellInfoEvent` SHALL be raised for every header cell rendered during PDF export. The argument SHALL expose `Cell`, `Column`, `Style`, `PdfGridColumn`, `RowIndex`, and `ColumnIndex`.

---

### Requirement: PdfAggregateTemplateInfo

The `PdfAggregateTemplateInfo` event SHALL be raised for every aggregate cell rendered in the PDF output. The argument SHALL expose `Cell`, `Column`, `Value`, `Style`, `GroupKey`, and `AggregateType`.

---

### Requirement: PdfGroupCaptionTemplateInfo

When `GridGroupSettings.CaptionTemplate` is configured and `PdfGroupCaptionTemplateInfo` is subscribed, the event SHALL be raised for each group caption row during PDF export.

### Requirement: OnExcelExport

The `OnExcelExport` action (`Action<object>`) SHALL be raised at the start of Excel or CSV export, before data processing begins.

#### Scenario: OnExcelExportRaisedBeforeExport
- **GIVEN** `OnExcelExport` is subscribed
- **WHEN** `ExportToExcelAsync()` is invoked
- **THEN** the handler is called before any worksheet rows are written

---

### Requirement: OnPdfExport

The `OnPdfExport` action (`Action<object>`) SHALL be raised at the start of PDF export, before data processing begins.

---

### Requirement: ExportComplete

The `ExportComplete` action SHALL be called after the export file has been successfully pushed to the browser (download path only). It SHALL NOT be called when `asMemoryStream = true`.

#### Scenario: ExportCompleteNotRaisedForMemoryStream
- **GIVEN** `ExportComplete` is subscribed
- **WHEN** `ExportToExcelAsync(asMemoryStream: true)` is called
- **THEN** `ExportComplete` is NOT invoked

#### Scenario: ExportCompleteRaisedForDownload
- **GIVEN** `ExportComplete` is subscribed
- **WHEN** `ExportToExcelAsync()` (browser download) completes successfully
- **THEN** `ExportComplete` is invoked with `"Success"`

---

### Requirement: DataReadyEvent

The `DataReadyEvent` (`ExcelQueryCellInfoEvent`-adjacent; internal event `"DataReady"`) SHALL be fired after the export data query completes, allowing consumers to override `DataReadyArgs.Data` (replace records) and `DataReadyArgs.Aggregates` (replace aggregate values) before the document is rendered.

#### Scenario: DataReadyOverridesRecords
- **GIVEN** a `DataReadyEvent` handler replaces `args.Data` with a filtered list
- **WHEN** export runs
- **THEN** only the records from the replaced list appear in the output document

---

### Requirement: Theming

The export engine SHALL apply an `AutoFormat`-based theme by default (`Theme = "default-theme"`). Setting `Theme = "none"` SHALL suppress all theme styling. `ExcelExportProperties.Theme` and `PdfExportProperties.Theme` MAY provide per-run overrides for header, caption, and record cell fonts, colors, and borders.

#### Scenario: DefaultThemeApplied
- **GIVEN** no theme override is provided
- **WHEN** export runs
- **THEN** header, record, and caption cells are styled according to the default AutoFormat theme

#### Scenario: NoThemeSuppressesStyles
- **GIVEN** `Theme = "none"` is set on the exporter
- **THEN** no `CopyStyles` or `CopyBorders` calls are made and cells are rendered with no styling

---

### Requirement: AutoFit

`ExcelExportProperties` SHOULD support an auto-fit column width option. When `IsAutoFit = true`, column widths SHALL be determined by the cell content rather than the grid's configured pixel widths.

---

### Requirement: ExcelHeaderAndFooter

`ExcelExportProperties.Header` and `ExcelExportProperties.Footer` MAY define custom header/footer rows to prepend or append to the worksheet. The number of rows and their cell values are driven by `ExcelExportHeader.HeaderRows` / `ExcelExportFooter.FooterRows` and associated `Rows[].Cells[]` definitions.

---

### Requirement: PdfPageTemplateHeaderFooter

`PdfExportProperties.Header` and `PdfExportProperties.Footer` MAY define PDF page template elements. The export engine MUST support `ContentType.Text`, `ContentType.Image`, `ContentType.Line`, and `ContentType.PageNumber` content types within those templates.

#### Scenario: PageNumberInPdfFooter
- **GIVEN** `PdfExportProperties.Footer.Contents` contains a `ContentType.PageNumber` item with format `"Page $current of $total"`
- **WHEN** PDF export runs
- **THEN** each PDF page footer shows the correct current-page and total-page numbers

---

### Requirement: PdfPageSettings

The PDF document page size SHALL default to A4 (`595 × 842` pt). `PdfExportProperties.PageSize` (enum `PdfPageSize`) and `PdfExportProperties.PageOrientation` (enum `PageOrientation`: `Portrait` | `Landscape`) SHALL override the defaults. The export engine MUST map every `PdfPageSize` enum value to the correct point dimensions.

---

### Requirement: AutoSpanPreservation

When `SfGrid.AutoSpan` is not `AutoSpanMode.None`, the export engine MUST honor `Cell.RowSpan` and `Cell.ColSpan` values on data cells — applying equivalent `RowSpan` / `ColumnSpan` in the output document.

#### Scenario: RowSpanPreservedInExcel
- **GIVEN** a cell has `RowSpan = 2` from the grid's `AutoSpan` calculation
- **WHEN** Excel export runs
- **THEN** the corresponding Excel cell has `RowSpan = 2`

---

### Requirement: ForeignKeyColumnExport

When a column is a foreign-key column (`IsForeignColumn() == true`), the export engine SHALL resolve the display value via `GridUtils.GetForeignData` and write the resolved value (not the raw foreign-key value) to the output cell.

#### Scenario: ForeignKeyDisplayValueInExport
- **GIVEN** a foreign-key column mapping `EmployeeId → EmployeeName`
- **WHEN** export runs
- **THEN** the exported cell shows `EmployeeName`, not `EmployeeId`

---

### Requirement: BooleanValueLocalization

Boolean cell values SHALL be exported as localized strings. The export engine MUST call `Localizer.GetText("Grid_True")` and `Localizer.GetText("Grid_False")` to resolve the display strings.

#### Scenario: BooleanTrueLocalized
- **GIVEN** the active locale has `Grid_True = "Yes"`
- **WHEN** a boolean column with value `true` is exported
- **THEN** the exported cell displays "Yes"

---

### Requirement: EmptyGridBody

When the data source is empty (count = 0), the export engine SHALL render a single row spanning all columns that displays the localized empty-record text (resolved via `Localizer.GetText("Grid_EmptyRecord")`).

#### Scenario: EmptyTextInExportedDocument
- **GIVEN** the grid has no data rows
- **WHEN** export runs
- **THEN** the output document contains one data row with a single merged cell showing the empty-record text

---

### Requirement: VirtualizationExport

When `SfGrid.EnableVirtualization = true` and grouping is not active, the export engine MUST bypass the virtual viewport and fetch all records via `GenerateAndExecuteQuery` before rendering.

#### Scenario: VirtualGridExportsAllRows
- **GIVEN** a grid with virtualization enabled showing 20 rows in the viewport but 500 total
- **WHEN** `ExportToExcelAsync()` (AllPages) is called
- **THEN** the exported document contains all 500 rows

---

### Requirement: InfiniteScrollExport

When `SfGrid.EnableInfiniteScrolling = true` and `ExportType = AllPages`, the export engine MUST reset infinite-scroll state via `InfiniteScrollModule.ResetInfiniteProperties` before fetching data (when `InfiniteScrollSettings.EnableCache = false`).

---

### Requirement: ActionFailureOnExportError

If an exception is thrown during data processing inside `ExportHelper<T>.DataProcess`, the engine SHALL invoke `GridEvents.OnActionFailure` (if subscribed) with a `FailureEventArgs` containing the exception.

#### Scenario: ExportDataFailurePropagated
- **GIVEN** the data source throws an exception during export query execution
- **WHEN** export is triggered
- **THEN** `OnActionFailure` is raised with the exception in `FailureEventArgs.Error`

## Technical Notes

- **Implementation**:
  - `Internal/Export/GridExcelExport.cs` — Excel + CSV renderer (2549 lines)
  - `Internal/Export/GridPdfExport.cs` — PDF renderer (2833 lines)
  - `Internal/Export/ExportHelper.cs` — Shared data-fetching and utility helpers
  - `Internal/Export/ExportModel.cs` — Internal enums (`DocumentOption`, `FontWeight`, `GridTableCellType`, `TableOptions`) and `ExportModel` placeholder
  - `Internal/Export/AutoFormat.cs` — Theme/style presets

- **Public API entry points** (on `SfGrid<TValue>`):
  - `Task ExportToExcelAsync(ExcelExportProperties? props)`
  - `Task<MemoryStream> ExportToExcelAsync(bool asMemoryStream, ExcelExportProperties? props)`
  - `Task ExportToCsvAsync(ExcelExportProperties? props)`
  - `Task<MemoryStream> ExportToCsvAsync(bool asMemoryStream, ExcelExportProperties? props)`
  - `Task ExportToPdfAsync(PdfExportProperties? props)`
  - `Task<MemoryStream> ExportToPdfAsync(bool asMemoryStream, PdfExportProperties? props)`

- **Guard properties**: `AllowExcelExport` (gates Excel + CSV), `AllowPdfExport` (gates PDF)

- **JS Interop**: Browser-download path calls `sfBlazor.Grid.exportSave(fileName, base64)` via `GridModel.InvokeMethod`

- **External library dependencies**:
  - `Syncfusion.ExcelExport` — `Workbook`, `Worksheet`, `Row`, `Cell`, `Column`
  - `Syncfusion.PdfExport` — `PdfDocument`, `PdfGrid`, `PdfGridRow`, `PdfGridCell`, `PdfFont`, `PdfPage`

- **Threading**: Excel and PDF `ExecuteResult` methods are run via `Task.Run(...)` off the Blazor sync context; data pre-processing (`DataProcess`) is awaited on the sync context with `ConfigureAwait(true)`

- **Dependencies**: filtering (date filter value update), grouping (caption rows, indent cells, grouped data iteration), aggregates (footer + group-footer + caption summary rows), foreign-key (value resolution), virtualization (bypass virtual viewport), infinite-scroll (state reset), localization (empty text, bool labels)

- **Toolbar integration**: `ToolbarStateChanged` event is triggered with `"ExcelExporting"` / `"ExcelExportCompleted"` and `"PdfExporting"` / `"PdfExportCompleted"` to allow toolbar button state updates
